# Arthur Consent and Capability Boundaries

Arthur is a **local-first Windows desktop prototype**. Each capability must be observable, independently enabled, and revocable by the signed-in user. A displayed command plan is never an instruction to run raw generated shell text.

| Capability | Default state | Approval boundary | Retention and revocation |
| --- | --- | --- | --- |
| Local wake-word listening | Off | The user selects a verified local model and explicitly enables listening. | Audio is processed in memory only; tray pause, exit, and disabling the switch stop the listener. |
| Voice visualizer | Idle | It opens when the user starts a command session or an approved wake-word detection occurs. | It receives only a transient level value; it does not save audio. |
| Language preference and library | Profile default | “Speak in …” changes the active reply preference only after Arthur repeats the requested language for confirmation. The local Language library may catalogue and favourite language names, ISO codes, native labels, writing systems, community-review states, and carefully qualified vitality context. The user may select a local ISO 639-3 identifier table for discovery and prepare an explicitly unverified colloquial review preview only after supplying language, region, expression, meaning, source/community attribution, and a sensitivity note. A source-confirmed preview also requires a named recognised source, HTTPS evidence URL, use context, and reviewer attestation. | Selecting or preparing a query never downloads a pack, opens the microphone, translates, searches, or sends text. A selected identifier table is staged locally only and is neither uploaded nor redistributed. The library includes no fabricated slang or verified cultural claims. **Source-confirmed** means only that the named evidence was checked; it never equals community review, publication permission, or automatic-use approval. Source-confirmed previews, review previews, and private drafts cannot publish, translate, search, speak, train on, or send their entries. Speech, translation, and research in a non-ready language require a separately approved local pack or provider. |
| App launch | Off until confirmed | Fixed Windows URI/safe launch templates only; each launch is previewed and confirmed. | No command text, window content, or app activity is retained as a side effect. |
| Messaging | Draft only | Arthur prepares a recipient and draft; the user must inspect and send through the messaging app. | Arthur does not send automatically or retain contact/message content unless separately saved as a note. |
| Risk advisory | On | Arthur speaks a concise caution before presenting a medium-risk confirmation; blocked activity is refused. | Spoken advisories are local and are not recorded by default. |
| Voice style/pitch | Local preference | User chooses a locally available Windows voice and rate; pitch is labelled unavailable where the engine cannot support it. | Preferences can be reset; no biometric profile is created. |
| “Clone my voice” | Off | Arthur requests a specific provider selection, a separate consent statement, sample duration, and an export/delete policy. | No recording, upload, synthesis, or third-party enrolment happens in this prototype. |
| Camera/microphone style learning | Off | The user selects a purpose and grants a single-session capture request with a visible indicator. | The prototype records no camera frame or microphone sample; future storage must be local, reviewable, exportable, and erasable. |
| Smart-home integration | Disconnected | User enters/authorizes a selected local hub and confirms each discovery or device action. | No network scan, device discovery, pairing, or command runs automatically. |
| GitHub updates | Manual only | A user first confirms metadata retrieval, then separately confirms a selected asset download, then separately chooses whether to open the completed installer. | Downloads are placed in a user-visible updates folder and may be deleted; no background polling or auto-installation occurs. |
| Touch workspace navigation | On where Windows reports a touch screen | Finger swipes, pinch zoom, drag-to-reorder, and discard gestures only affect Arthur’s current workspace. Discard always presents an undo/review affordance. | Arthur retains only the workspace arrangement preferences that the user chooses to save. It does not inspect other applications’ touch input. |
| Camera-based air gestures | Off | The user must enable the feature, choose a local camera, see the visible “camera active” indicator, and approve the gesture set before capture starts. A gesture can only affect Arthur’s workspace; any consequential PC action is separately previewed and confirmed. | Frames and hand landmarks are processed transiently in local memory. No video, image, or biometric template is written, uploaded, or shared. Disabling the feature, using the tray pause, closing Arthur, or revoking consent stops capture immediately. |
| Protected Spatial-room access | Locked until set up | The user selects one access method: local password, OS-managed Windows Hello, or experimental local-camera face access. Voice/text requests are first reviewed, then require the selected method. Every optional adapter installation, user-started local-camera readiness test, enrolment, and face verification needs a separate visible user approval. A local accessibility tone is off by default and can be muted. | Password mode stores only a salted verifier in Windows Credential Manager. Windows Hello mode leaves face/PIN entirely to Windows. Experimental local-camera mode keeps no raw photo, video, or failed frame, stores only an encrypted local recognition model, uses a key and salted recovery-secret verifier in Windows Credential Manager, and provides delete/re-enrol controls. After three completed non-matches, it keeps only a short local counter/timer and pauses checks for 60 seconds; cancel, unavailable hardware, and permission errors do not count. It is not equivalent to Windows Hello and never uploads biometric data. |
| Symptom support | Available as a guided conversation | The user voluntarily enters symptoms. Arthur presents health information, possible urgency levels, and care-seeking prompts; it does not claim to determine a disease or replace clinical assessment. | Symptom text is not stored unless the user deliberately saves it as a private note. The user can edit or delete that note. |

## Safety invariants

Arthur will not run arbitrary shell text, perform network scanning, collect credentials, bypass controls, exploit systems, auto-send messages, auto-launch installers, silently access a camera or microphone, or represent a provider placeholder as a connected integration. Arthur stores biometric material only when the user separately selects experimental local-camera face access and completes its explicit enrolment consent; it stores an encrypted local recognition model rather than a raw face image or video, never uploads it, and supports deletion. The browser preview models these boundaries but does not execute desktop commands, access devices, or save credentials.

> **Health boundary:** Arthur is not a medical professional. Its symptom-support experience is informed guidance rather than a medical diagnosis. It must prompt urgent professional or emergency care for severe or rapidly worsening symptoms, including breathing difficulty, chest pain, signs of stroke, severe allergic reaction, loss of consciousness, or immediate safety concerns.
